# Changelog

What changed between versions, and — because a template only reaches a project
that already ran `init` when someone copies it across — **what to re-copy by
hand**. `nextjs-fsd config show` prints the version a project was scaffolded
with; if it is older than the CLI you are running, read down to it.

Only versions with a `v*.*.*` tag are on npm. 0.2.0 and 0.3.0 were released
into the repository but never tagged, so `npm install @nakedev/nextjs-fsd`
still resolves 0.1.1.

## 0.3.0 — in main, not tagged

Everything in this version came out of the first project built on these
templates, three weeks in.

### Fixed — re-copy these into a project generated by 0.2.0

The four are one bug wearing four faces: clearing cache state does not
re-render a component that was not going to re-render anyway.

- `shared/api/query-client.ts` **resets** `sessionKey` instead of removing it.
  `removeQueries` does not notify the observers mounted on the entry, so a
  sidebar or a route guard kept drawing a session that was over while the page
  under it showed a 401, and nothing ever saw `isError`.
- `shared/auth/session.ts`: `useLogout` redirects to `/login` from inside the
  function that ends the session, not from each button's `onSettled` — the
  call site that forgot the line is how this was found.
- `useSession` goes stale after a minute rather than five. That value is how
  long the shell may keep looking normal for a session that ended elsewhere.
- `_pages/login/ui/login-form.tsx` sends someone who already has a session
  past the form, honouring the `?next=` they arrived with.

### Added

- `generate layout <name> --guard` — one `useRequireSession` caller for every
  route under a layout. A page that guards itself is fine alone and races the
  shell as soon as both do it, so `generate page --auth` now says so when it
  finds a guarded layout.
- `generate page --model` — the file a slice's `api` segment gets, written
  into `model/` and kept internal to the slice.
- `init` writes a `commit-msg` hook (shape only: a Conventional Commit subject;
  language, tickets and emoji stay the project's call) and points
  `core.hooksPath` at it — unless husky owns that setting, it points somewhere
  else already, or there is no repository. `--no-hooks` skips it.
- `docs/fsd.md` and the skill gained: inline-vs-toast, `shared/<domain>/` over
  a premature `entities/`, that a catalog is a plain object so i18n needs no
  second shape from this CLI, and — for a Thai project only — the three
  typography rules Latin-tuned defaults get wrong.

### Changed

- `init` writes what is missing instead of refusing the whole batch over a
  file the project already has, and names each one it left alone. A flat
  ESLint config that already contains `no-restricted-imports` gets neither
  `eslint.fsd.mjs` nor the spread: flat config replaces a rule's options
  rather than merging them, so two sets do not add up.

## 0.2.0 — released into the repository, not tagged

Minor rather than patch: `add auth` writes `require-session.test.ts` on bun,
which npm projects did not get before, and `sessionKey` moved from
`shared/auth/session.ts` to `shared/api/query-client.ts` — a re-generated file
imports it from somewhere else than it used to.

- `useRequireSession` carries the path as `?next=`, and `safeNext` keeps the
  redirect on the same site (an unchecked `next` is an open redirector wearing
  your own domain, CWE-601).
- The QueryClient ends the session on any 401, from a query or a mutation,
  rather than only on the session query's own.

## 0.1.1

The README, rewritten to the depth go-scaffold's has: per-command reference
with options and generated file trees, install, quick start, project
structure, and what to edit after generation. 0.1.0 went to npm from a working
copy that predated it, and npm versions are immutable, so the rewrite could
only reach the registry as a new version. Also the release pipeline that
publishes from a verified tag instead of from someone's working copy.

## 0.1.0

First release: `init`, `generate page|slice|layout`, `add error-handling|auth`,
the two linters, the skill and `docs/fsd.md`.
